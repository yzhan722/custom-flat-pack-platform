> 当前阶段：方向探索 / Pre-PRD。

# 1. 项目最初起点

最初问题来自 **房车橱柜生产自动化**。

初始设想是：

> 用户/设计师简单描述房车橱柜需求，系统自动完成设计、建模、拆单、开料、CNC、五金齐套、分拣和出库。

例如：

```text
Sprinter 170
左侧厨房 1800mm
800mm 高
500mm 深
水槽 + 双灶
3 个抽屉 + 2 个柜门
15mm 轻量板
冰箱预留 520×550×850
```

理想链路：

```text
自然语言需求
↓
需求结构化
↓
参数化设计
↓
3D 模型
↓
工程校验
↓
BOM
↓
Nesting
↓
CNC
↓
标签
↓
分拣
↓
五金齐套
↓
出库
```

最初判断：

- 技术上可实现；
- 房车柜体具有大量重复模块，适合参数化；
- AI 不应该自由生成生产模型；
- AI 负责理解需求；
- 参数化 CAD + 制造规则负责确定性生产；
- 最终生产前必须有人确认。

---

# 2. 原始工厂背景

现有业务/场景背景：

- 澳洲小型木工 / 柜体加工场景；
- 预计日产约 10 张板左右；
- 对 CNC 开料、自动拆单、Nesting、标签、生产自动化有明确兴趣；
- 此前关注过弘亚、南兴、星辉等 CNC / 板式家具设备厂商；
- 更关心小型工厂实际 ROI，而不是大型家具厂 MES/ERP；
- 技术路线倾向：
  - 先跑通；
  - 再自动化；
  - 最后形成闭环；
- 不希望一开始重投入大型工业软件或复杂 ERP。

---

# 3. 第一轮技术结论：不要让生成式 AI 直接控制生产

核心原则：

> **CAD / 参数模型是生产真相，AI 不能直接从自然语言生成最终 G-code 并驱动 CNC。**

建议结构：

```text
自然语言 / 表单
↓
LLM 需求解析
↓
结构化 Design JSON
↓
参数化模型
↓
制造规则
↓
仿真 / 校验
↓
人工确认
↓
BOM / CAM / Nesting
↓
CNC
```

原因：

生成式 AI 擅长：

- 理解模糊需求；
- 对话修改；
- 生成候选方案；
- 解释方案取舍。

但生产必须依赖：

- 固定板厚；
- 接合规则；
- 五金规则；
- 孔位规则；
- 抽屉间隙；
- 封边规则；
- 刀具和加工能力；
- 安全约束；
- 明确且可复现的数据模型。

# 4. 房车阶段的参数化思路

当时认为应该建立三个核心数据库：

## 4.1 车型参数库

例如：

```text
Sprinter 144
Sprinter 170
Sprinter 170 EXT
Ford Transit
Toyota HiAce
Ducato
...
```

包含：

- 车壁；
- 地板；
- 车顶；
- 轮拱；
- 窗；
- 滑门；
- 后门；
- 加强筋；
- 禁装区域；
- 水电设备；
- 车辆曲面。

## 4.2 柜体模块库

例如：

```text
BASE_01 单门地柜
BASE_02 双门地柜
BASE_03 三抽地柜
BASE_04 水槽柜
BASE_05 炉灶柜
BASE_06 冰箱柜

OH_01 单门吊柜
OH_02 双门吊柜

TALL_01 衣柜

BED_01 床箱

RV_01 轮拱柜
RV_02 弧形侧板柜
```

## 4.3 制造规则库

例如：

```text
Panel = 15mm lightweight plywood
Back = 6mm
Drawer side clearance = 12.5mm
Front gap = 2mm
Joint = Dado + Screw
Dado depth = 5mm
Visible edge = Edge band
```

结论：

> 真正的核心资产不是 AI 模型，而是 **参数化产品库 + 制造规则库**。

# 5. 仿真与世界模型的第一次定位

讨论过“仿真”和“世界模型”应该什么时候使用。

## 5.1 仿真

判断：

> 仿真应很早进入生产链，是工程审核器。

设计阶段：

- 柜门能否打开；
- 抽屉是否碰撞；
- 模块是否冲突；
- 空间是否足够；
- 柜体结构是否合理。

制造阶段：

- 刀具碰撞；
- 刀路越界；
- 孔位冲突；
- 板件尺寸；
- CNC 可加工性；
- 板材利用率；
- 真空吸附；
- 封边可实现性。

房车阶段还包括：

- 总重量；
- 重心；
- 行驶振动；
- 固定点载荷。

早期不一定做复杂 FEA，可以先：

```text
规则引擎
+
几何碰撞
+
简化物理模型
```

比较：


- 尺寸异常；

原产品：

> AI 房车橱柜设计生产系统

> 房车空间设计与定制制造平台

- CAD；
- Dado；
- 板厚；
- Nesting；

C 端真正关心的是：

```text

↓

↓

↓

↓

```

因此制造从“产品入口”退到后台，成为履约能力。

# 12. 当前用户输入方式假设

例如用户说：

> 我这里有一个 1800mm 宽、600mm 深的位置，想做一个电视柜，下面 4 个抽屉，两边储物，中间放音响，白色，预算 A$1500 以内。

AI 结构化：

```text
Product: TV Cabinet
Width: 1800
Depth: 600
Drawer: 4
Storage: 2
Audio Space: Yes
Colour: White
Budget: 1500
```

然后生成：

- A：储物最多；
- B：视觉最简洁；
- C：成本最低。

用户继续用自然语言修改：

> 中间再宽一点。

> 抽屉改成三个。

> 不要拉手。

关键原则：

> **AI 修改参数，不重新随机生成不可控模型。**

# 14. 当前仿真定位

在最新 C 端家具平台方向下，仿真依然非常重要。

但前台应该消费化。

后台：

```text
Collision check
Structural rule check
Manufacturability check
Packing calculation
```

用户前台应该看到：

> 抽屉打开后会碰到旁边家具。

> 这个层板跨度过大，需要增加中间支撑。

> 如果柜深从 450mm 改为 520mm，储物增加，但价格增加 A$120。

仿真因此不只是安全校验：

> **它也可以成为实时设计反馈和交互能力。**

# 19. 平台与工厂关系的关键问题

当前存在两种可能：

## 模式 A：自营制造优先

平台：

```text
获客
+
设计
+
报价
+
自营工厂生产
+
交付
```

优势：

- 质量可控；
- 数据完整；
- 适合早期验证；
- 可以快速形成制造规则。

问题：

- 重资产；
- 地理扩张慢。

---

## 模式 B：制造网络平台

平台把标准化生产包发送给本地合作工厂：

```text
Design Package
+
BOM
+
Nesting
+
Machine Instructions
+
QC Rules
```

不同城市的 CNC 工厂负责生产。

优势：

- 轻资产；
- 可扩张；
- 本地生产降低物流。

问题：

- 机器差异；
- 刀具差异；
- 板材差异；
- 工艺差异；
- QC；
- 工厂标准化；
- Post Processor；
- SLA。

比较合理的路径可能是：

> **早期自营 / 单工厂验证 → 中期复制标准 → 后期开放制造网络。**

但这一点需要 Work 重新分析，不应直接接受。

# 20. 一个重要类比

# 21. 当前最大的未验证假设

Work 模式需要重点挑战以下问题。

## 21.1 用户需求是否真的适合自然语言输入？

普通消费者表达：

> “我想做一个好看的柜子”

离真正制造还非常远。

需要判断：

- AI 对话需要多复杂；
- 是否最终仍需大量尺寸输入；
- 是否应该以模板/配置器为主、语言为辅；
- 图片/扫描是否比自然语言更重要。

---

## 21.2 C 端是否真的需要完全定制？

竞争对象不是 CAD 软件。

而是：

- IKEA；
- Bunnings；
- Amazon；
- 定制橱柜公司；
- 木工；
- 平板家具；
- 本地 Cabinet Maker。

需要证明：

> 哪些需求同时满足“标准家具解决不了”且“找传统木工太贵/太麻烦”。

可能的 wedge 市场：

- 尺寸特殊的壁龛；
- 洗衣房柜；
- 车库储物；
- Home Office；
- TV Unit；
- Wardrobe Insert；
- Alcove Cabinet；
- 房车 / Caravan；
- Rental-friendly storage；
- 小户型。

Work 应重新筛选。

---

## 21.3 定制是否会导致 SKU 爆炸？

即使使用参数化模型，也可能产生：

- 不同板材；
- 五金；
- 尺寸；
- 包装；
- 物流；
- 返工；
- 安装问题。

需要判断怎样定义：

> **Mass Customisation**

而不是：

> 无限自由定制。

---

## 21.4 自动设计和人工审核边界在哪里？

哪些订单：




# 23. 数据模型初步方向

整个系统可能需要统一 Design Schema。

例如：

```json
{
  "product_type": "tv_cabinet",
  "space": {
    "width": 1800,
    "height": 900,
    "depth": 600
  },
  "modules": [
    {
      "type": "drawer",
      "count": 3
    },
    {
      "type": "storage",
      "count": 2
    }
  ],
  "material": "white_melamine_18",
  "style": "minimal",
  "budget": 1500
}
```

然后：

```text
User Intent
↓
Design Schema
↓
Parametric Model
↓
Manufacturing Schema
↓
Machine-specific output
```

重要架构原则：

> **设计数据与具体 CNC 机器解耦。**

# 25. 安装体验可能是重要差异化

传统 flat-pack 最大痛点之一不是生产，而是安装。

平台可利用设计模型自动生成：

```text
Assembly Graph
```

即：

```text
A + B
↓
C
↓
D
↓
Hardware E
```

然后转换为：

- 动画；
- 3D；
- AR；
- QR；
- AI 安装助手。

长期甚至可以：

> 用户摄像头对准当前家具，系统判断装到了哪一步以及下一步应该怎么做。

这可能是视觉 / 世界模型真正有价值的地方之一。

# 26. 当前产品原则

现阶段倾向的原则：

1. **需求表达简单化**
2. **生产模型确定性**
3. **AI 不直接制造**
4. **无限定制改为受约束的大规模个性化**
5. **实时看到价格影响**
6. **实时看到设计约束**
7. **订单最终一定能制造**
8. **制造数据与机器解耦**
9. **早期人工审核不是失败**
10. **逐步用数据减少人工审核**

# 27. 当前建议的版本路线（待 Work 挑战）

## V0 — 工厂内部验证

目标：

证明：

> 一个结构化订单可以自动产生正确的板件和制造文件。

范围：

- 1 种板材；
- 1 套五金体系；
- 3~5 个柜体模块；
- 1 台 CNC；
- 内部使用。

---

## V1 — C 端 MVP

目标：

证明：

> 普通消费者可以完成一个定制柜订单。

流程：

```text
模板
+
自然语言修改
+
尺寸
↓
3D Preview
↓
报价
↓
人工 Engineering Review
↓
生产
↓
Flat-Pack Delivery
```

世界模型暂时不是硬依赖。

---

## V1.5 — 空间理解

增加：

- 视频；
- 手机扫描；

- 自动识别空间约束。

---

## V2 — 高度自动化

增加：

- 自动工程审核；

- 板材供应商；
- 安装商；
- 物流。

形成平台。
